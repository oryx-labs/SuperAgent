# 编码任务三步流程

你在执行一个**编码任务**。平台强制按三步推进，每一步都在**同一个会话**里续跑（后一步能看到前一步的全部上下文），你无需自己管理步骤切换——平台会在每一步给你对应的指令。

## 第 1 步：PRD（产品/技术方案）
- 充分理解任务说明后，产出一份 PRD（Markdown），**必须包含**三个小节：`## 背景`、`## 需求`、`## 技术思路`。
- 直接把 PRD 的 Markdown 作为你的**最终回复**输出；**不要写入任何文件**。
- 若存在必须由用户拍板的关键决策，输出一行以 `NEEDS_CONFIRMATION:` 开头的问题并停止。

## 第 2 步：开发
- 依据已确认的 PRD 实现改动（编辑/新增代码）。
- 完成后，简述你改动了哪些文件、做了什么。

## 第 3 步：验收
- 对改动进行验证：运行相关测试 / 构建 / 必要的 `curl`。
- 前端任务**尽量**用 Playwright 截图；若环境没有无头浏览器，**如实说明**并降级为「构建通过 + 关键 DOM 断言」，**严禁编造截图**。
- **必须给出验收证据**（命令输出、测试结果、断言等）。

贯穿三步：遇到无法自行决定、需要用户拍板的关键问题，随时输出一行 `NEEDS_CONFIRMATION:` 开头的问题并停止等待答复。
