项目第二版：代码仓库、项目资料目录、项目共同上下文

把「项目」从成员容器升级成推进工作的单位：可以配置代码仓库，有自己的资料目录，项目里所有 Agent 共享同一份项目上下文。

背景

第一版的项目只是成员容器：放进 Agent、拉进同事，大家能用同一批 Agent，看到项目里产出的任务和文件。真正推进工作时缺三样东西：

  • 代码在哪：开发类项目的编码任务每次都要重新说仓库，项目层面没有记录。
  • 资料在哪：文件只按人归档，项目没有自己的目录，同一份资料在几个项目间共享也没有办法。
  • 共识在哪：项目的目标、规范、术语和做过的决定只在某个人的对话里，换一个 Agent、换一次会话就丢了。

这三样都应该是公司资产，沉淀在项目上，而不是某个人或某个 Agent 身上。

需求

R1 项目代码仓库 负责人配置

一个项目可以配置 0 到多个仓库，每个仓库有：名称、地址（本地路径或 git 地址）、默认分支、交付方式（merge 或 pr）、用途说明。

  • 不加项目类型字段：开发类还是内容类，由有没有配置仓库自然区分。
  • 项目内 Agent 调 coding_targets 时，先列出本项目的仓库，再列管理员开放的目录和最近用过的位置。
  • 一个任务要改多个仓库时，第一版拆成每个仓库一个子任务，不做单个任务同时改多个仓库。

R2 项目资料目录 成员共建

资源页里每个项目有一棵共享目录树（最多 3 层），和个人目录是两套，项目成员都能看到。

  • 文件只存一份，通过「挂载关系」同时属于：来源 Agent、一个或多个项目目录、个人目录。
  • 同一个文件可以放进多个项目目录，但放的人必须本来就能看到这个文件，并且是目标项目的成员。
  • 从项目目录移出只删挂载关系，不删文件；删项目目录时，里面的文件和子目录退回上一级。
  • 项目内 Agent 新产出的文件自动放进项目目录：Agent 指定了已有子目录就放那里，没指定或拿不准就放在根下。
  • 迁移：已经有 project_id 的旧文件，启动时挂到对应项目目录的根下（可重复执行，移出过的不会再挂回来）。

R3 项目共同上下文 自动带进 Agent

层内容谁写
项目说明目标、背景、规范、术语负责人
资料索引项目目录里的文件（目录、标签）和项目仓库（用途），每项一行自动生成
项目记忆决策、约定、踩过的坑；每条记录来源：哪个 Agent、哪次对话或任务、谁发起的成员；Agent 通过 MCP 工具 project_memory_write（新增；带 memory_id 即修改已有的一条，不单设 update 工具）
  • 三层自动带进项目内每个 Agent 的每一轮对话和每一轮任务（包括复用会话），项目外的 Agent 拿不到。
  • 总长有上限（6000 字）；超出时说明截短，资料索引和项目记忆只列标题，Agent 用 project_context_read 按需读全文或单条记忆。

R4 权限

  • Agent 仍然只能属于一个项目。
  • 负责人：改项目说明、仓库和成员。成员：往项目目录加文件、建目录，增删改项目记忆。
  • 项目归档后，资料、记忆和仓库配置全部只读（读取照常）。

R5 界面

  • 项目页增加「资料」「仓库」「说明与记忆」三个标签。
  • 资源页的目录树里有「项目」分组，显示每个项目的目录；文件可以拖进项目目录，查看某个项目时可以拖到「移出」区域移出；文件预览里显示所在项目，可以加入或移出。
  • 沿用黑白灰加品牌蓝；SuperAgent / Agent / Share Agent 不翻译；中英文都有。

技术思路

层改动
superagent-coreProjectRepo / ProjectBrief / ProjectMemory + ProjectContextStore；ProjectFolder + ProjectFolderStore；ProjectAccess 增加成员与只读检查、任务所属项目、项目仓库、context(agentId, taskId)
superagent-storageMySQL 表 project_repo、project_brief、project_memory、project_folder、project_file_placement，都带 company_id，查询按 TenantContext.require() 过滤
superagent-projectProjectService：仓库、说明、记忆、上下文拼装（ProjectContextBuilder）、旧文件迁移；ProjectMcpTools（project_context_read、project_memory_write）；ProjectFileMigration 启动时逐个公司执行
superagent-filesProjectFolderService：项目目录树、挂载/移出、Agent 按路径放进项目目录；文件可见性多一条「挂在用户所在的项目里」
superagent-task / agent任务每一轮的系统提示词和对话每一轮的系统提示词都拼进 ProjectAccess.context；coding_targets 先列项目仓库
superagent-web / uiController 只转发；projects.js 三个标签，file-folders.js 项目目录树与拖放

验收标准

  • 单测覆盖：配置并读取多个仓库；coding_targets 先列项目仓库；一个文件挂在多个项目目录、没有权限时不能放、移出不删文件；项目内 Agent 的提示词包含说明、索引和记忆，项目外的不包含；超出上限只带标题；Agent 写项目记忆并记录来源；归档后只读；旧文件迁移；租户隔离。
  • mvn -pl superagent-web -am test 通过。
  • 刷新页面后能看到项目的仓库、资料、说明与记忆，以及资源页里的项目目录。
