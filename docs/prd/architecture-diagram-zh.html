SuperAgent 技术架构

一个控制面服务所有公司，多家公司的数据放在同一个库里，靠公司字段区分。Agent 运行在多台物理机上的隔离沙箱里，每个员工一个；运行时做成插件，microVM、Docker 等都可以接入。控制面负责调度，各机器上的 Worker 负责执行。模型 Key 等敏感凭证始终不离开控制面。SaaS 和私有化部署用同一套代码，私有化只是只有一家公司。

多机部署与调用链路

运行时只允许这 5 条通信：控制面不直连沙箱，沙箱访问不到 Worker 和数据库。

三层的信任边界

每一层只持有完成本职必需的东西。

层信任负责持有绝不持有只能访问
控制面可信 接口、业务域、调度、模型网关、MCP 工具服务 数据库凭证、主密钥、模型 Key、员工的 OAuth 刷新令牌 — 数据库、对象存储、模型上游、飞书和钉钉；从不直连沙箱
Worker半可信 在本机启停沙箱并限制资源、转发输出流、准备工作区、上报心跳 自己的节点凭证（可以随时吊销） 数据库凭证、模型 Key、刷新令牌 控制面（主动长连接）、本机的运行时
沙箱不可信 运行 CLI，执行 Agent 的命令 单次运行令牌、员工本人的短期连接令牌、员工的工作区 以上全部，以及 Docker socket 控制面的 MCP 和模型网关；出网只经出口代理

同一套代码，三种部署方式

单机

控制面、Worker 和沙箱都在一台机器上，用 docker compose 拉起。三层的边界不变，以后扩成多台机器不用改架构。

多机

控制面至少两个实例，共用 MySQL 和对象存储。每台物理机跑一个 Worker，由调度器统一安排任务放在哪台机器上。

SaaS 与私有化

同一套源码。私有化就是只有一家公司，可以用 Docker 运行时；SaaS 里多家公司混跑，用 microVM 或 gVisor。
