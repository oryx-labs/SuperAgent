讨论稿。四周、16 节课，做出一个可运行的企业 SuperAgent 最小系统。课程面向有软件工程经验、已经使用过 AI 编程工具的开发者，从 DeepSeek Harness 团队提出的 Super-agent 架构思路出发，亲手建立员工工作入口、任务控制面和 Agent Worker：员工通过网页或事件发起工作，系统分派任务并持续运行，过程、成本、审批和交付物留在企业平台中。

课程定位

会用 Codex、Claude Code 写代码，与能设计一个供企业员工持续使用的 Agent 系统，是两种不同的工程能力。前者关注单个任务怎样做完；后者还要回答任务从哪里来、该由谁执行、执行时能访问什么、并发任务如何隔离、失败后怎样恢复、花了多少、谁来验收，以及工作结果如何留在企业。

DeepSeek 的 《Super-agent 设计探索：迈向更自主的 Agent 系统》给出了一条重要的系统路线：Router 维护跨信道的连续交互，Worker 隔离并行执行具体任务；事件驱动让 Agent 主动工作；异步调用、状态与环境分离、Watchdog 支撑长期运行。文章明确说明它是架构探索，公开原型也不是正式产品。本行动营以这些问题和设计方法为起点，完成我们自己的企业版 SuperAgent，而不声称复刻 DeepSeek 的内部系统或获得其官方授权。

课程的中央判断是：模型和 Coding Agent 会越来越强，企业仍需要一个掌管身份、任务、环境、权限、成本、审计和交付的工作系统。学员要把已经会写的 Web 服务、数据库、调度和部署能力，与 Agent 的 Session、Context、工具、沙箱和验证连接起来，做出一条可以运行、可以解释、可以检查的主链路。

我们要做出的 SuperAgent

课程以一家知识付费公司为例。产品经理在工作台提出"给会员平台增加续费提醒功能"，系统创建研发任务，把仓库、相关需求、验收标准和权限交给隔离的 Coding Agent；员工可以继续提问或修改要求，Agent 在后台开发、测试并交付代码和验证记录，高风险的发布动作等待人确认。同一平台还可以接收内容编辑的选题任务，调用不同工具生成可审阅的文章草稿。这两个工作场景共用任务、运行、审计与知识接入能力，业务工具和验收标准则不同。

四周的主场景是研发任务。它从 Chat 进入，后来增加定时和 IM 事件入口，最终至少完成一次"请求进入 → 创建 Task → 分派 Worker → 调用一种真实 Coding Agent → 持续返回事件 → 保存结果与用量 → 人工验收"的完整运行。内容生产作为迁移练习，用同一任务接口换一个业务目标和交付物，检查架构是否真能服务非程序员。

我们会参考现有 SuperAgent 项目代码作为工程素材：其中已有 Java/Spring 多模块骨架、Chat/Task 服务、Claude CLI 运行适配、事件流与初步 MCP 接口。课程设计不能把这些代码当作现成的生产级控制面。教学中会按从零建模的顺序解释每个对象为什么出现，再利用仓库中的实现或重构作实战练习。课程开始前需要把示例代码整理成可复现的教学起点。

四层职责与一条主链路

从产品到执行，SuperAgent 可以按以下职责理解：入口接收员工对话、定时触发与外部事件；控制面保存用户、项目、Task、策略、审批和审计，负责任务生命周期；Router 负责跨任务的语义判断、分派与对外交互；Worker 在独立环境中运行 Codex、Claude Code 或自建 Agent Runtime，读取知识、调用工具并交付结果。Router 是一项逻辑协调能力，可以由规则和模型共同实现，不必等同于一个 Spring 服务；控制面持有确定性的状态和权限，不能只保存在 Router 的模型 Session 里。

员工目标或外部事件 → 入口与身份 → 控制面建立 Task → Router 判别和分派 → Worker 在工作区执行 → 事件、成本与证据回写 → 人工验收或继续执行

四周按这条链路逐步建设。先决定产品目标和层间契约，再让 Worker 独立工作，随后接上控制面和 Web 入口，最后加入事件驱动与知识/任务 MCP。这样每周结束都有前一周没有的可观察能力。

面向谁，学到什么程度

学员需要会一门主流语言，理解 HTTP、数据库、并发、日志和部署，最好用过 Codex、Claude Code 或同类 Agent 处理真实项目。课程实现语言以 Java 21、Spring Boot 和 MySQL 为主，Agent 的具体供应商可替换。这里不重新教授 Java 语法，也不把课程做成"Spring 入门"。

结束时，学员应能解释 Router、控制面、Worker 与运行环境各自掌管什么；实现一个带真实 Agent 适配器、任务状态、事件流、人工验收和审计记录的最小系统；用一次研发任务和一次内容任务证明底座可以复用；在 Trace、成本与失败记录里说明系统还缺什么。真正的大规模分布式调度、MicroVM 池、完整多租户权限与生产级高可用属于继续演进的方向。它们会被放进架构和实验，不承诺在 16 节课内全部建成。

贯穿课程的工程判断

两种 Agent 运行方式。 第一种是自己控制模型请求、ReAct Loop 和工具执行，适合讲清 Agent Runtime 的基本机制；第二种是把 Codex、Claude Code 等原生 Coding Agent 作为 Worker 内的执行器，通过适配器管理 Session、流式事件、取消和用量。主项目会选择第二种跑通真实任务，同时做一个小型 Loop 实验，让学员知道哪些能力由现成 Agent 承担，哪些仍必须由 SuperAgent 承担。

两类路由。 任务路由决定哪个 Worker、哪个 Agent、哪个环境接手；模型路由决定自建 Runtime 调用哪个模型。对于封装了内部模型调用的 CLI Agent，平台能决定选用哪一种 Agent，并记录其返回的用量或费用，但未必能逐次改写它内部的模型请求。模型网关作为自建 Runtime 和受控 API 调用的可选实现，不作为课程完成的前提。成本优化首先要能归因到 Task、用户和项目，再讨论策略优化。

先保证事实，再增加自主性。 Task、Attempt、Agent Session、Event 和 Artifact 分开保存；权限校验、审批、取消和预算由系统实现；Router 和 Worker 使用模型做判断与执行。Watchdog 先检查可度量的超时、心跳和停滞，再讨论模型辅助判断是否跑偏。事件入口先经过规则过滤、去重和归属判断，只有需要语义理解的候选才交给模型。

课程大纲

第一周：先想清楚，再定义产品和架构

这一周不急于堆功能。学员先理解个人助手、持续运行的 Agent 与企业内部工作平台之间的能力变化，选定一个具体业务任务，把系统的责任划清楚。第四节结束时，后面三周需要实现的接口、状态和验收标准应当已经明确。

01｜AI 工程师怎样看一个持续工作的 Agent 系统

从 OpenClaw、Hermes Agent、Agent OS 和 DeepSeek 的 Super-agent 思路出发，讨论个人助手、长任务执行器与企业工作平台解决的不同问题。重点读 DeepSeek 文章提出的四个目标：连续、高效、主动和持久，并观察其背后为什么会出现 Router/Worker、事件过滤、异步执行与 Watchdog。课程要让学员从"我会调用模型和使用 Coding Agent"，走到"我能判断一个 Agent 系统缺哪一层工程能力"。作业是用自己的项目经验画出已会能力与新增能力的地图，选出最想亲手验证的一条链路。

02｜如果我来做 SuperAgent：先确定第一版要完成什么

我们把"做一个 SuperAgent"收窄为知识付费公司的研发请求：产品经理提交目标，系统建立可追踪的任务，Coding Agent 完成代码和测试，员工审核结果。围绕这件工作定义输入、用户身份、Agent 能力、任务状态、交付物和完成标准，再用内容编辑提交选题的场景检查抽象能否复用。学员要交出一页第一版产品定义和两组验收用例；模型、RAG、浏览器、审批与成本只在这两组任务需要时进入设计。

03｜从员工和管理员视角设计企业 AI 工作台

产品要让员工看见"工作"，管理员看见"运行和治理"。员工需要发起、追问、暂停、查看过程、审阅交付；管理员需要配置可用 Agent、工具、工作区、额度与审批规则，查看任务、费用和审计。我们会画出 Chat、Task、Activity、Approval、Artifact 的页面关系，尤其检查一个员工提出第二个需求时，前一个任务是否仍能独立推进。最后确定第一版只做哪些页面和管理动作，留下员工与管理员各一条可演示路径。

04｜画清 SuperAgent 架构：控制面、Router 与 Worker

把前三节的产品对象放到架构里：入口统一接收消息，控制面保存确定性状态和治理策略，Router 做任务理解与分派，Worker 在隔离工作区执行，事件和结果回到任务。要定义 Task、Attempt、Agent Session、Event、Artifact 的关系，以及启动、追加指令、取消、失败、等待确认、完成时各层怎样交互。学员画出时序图和模块边界，写出最小 Worker 契约；第二周可以先在命令行用这个契约运行 Worker，第三周再接入 HTTP 控制面。

第二周：先让 Worker 能可靠地完成任务

有了契约，先实现执行侧。只要 Worker 还依赖网页请求保持在线、进程退出就丢掉全部状态，后面的 Chat 和事件入口都会把问题放大。这周以一个真实 Coding Agent 适配器为主线，逐步加入运行状态、故障观察、用量记录和隔离策略。

05｜两种 Agent Runtime：自建 Loop 与原生 Coding Agent

先用一个最小 ReAct Loop 观察模型输出、Tool Call、Observation 和停止条件，弄清自己控制 Runtime 时需要承担哪些状态与错误处理。随后把 Claude Code 或 Codex CLI 作为执行器接入统一 AgentRunner 契约，管理启动、Session 恢复、流式输出、取消和结果归一化；再用一个 Mock Agent 验证接口确实可替换。课程主项目选择一条真实 Agent 执行链路，自建 Loop 保持教学实验的尺度。到课末，一个独立 Worker 应能接收任务说明，在指定 Workspace 里完成一次可检查的操作，并吐出结构化事件。

06｜运行时怎样持续工作：状态、异步与 Watchdog

执行时间从几秒变成几十分钟后，控制面不能同步等待模型，Worker 也不能只靠"进程还活着"表示任务正常。我们会设计任务领取、心跳、超时、重试、取消和事件回传，区分应用的 Task、一次 Attempt 与底层 Agent Session；再做一个最小 Watchdog，发现心跳停滞或反复失败后报警或移交人工。模型辅助判断是否跑偏作为扩展练习。学员主动中断一次 Worker，检查系统能否判断这项工作是可恢复、需要重试，还是结果未知。

07｜谁来做这项工作：Agent 选择、模型路由与用量归因

控制面根据任务类型、允许的工具、预估预算和运行环境选择 Agent 与 Worker；自建 Runtime 才进一步选择模型和 API 路径。我们会比较规则路由和模型判断的代价，做一个按任务类型选择执行器的策略，并将 CLI 返回的 token 或费用事件映射到任务、用户和项目。学员需要用两种任务展示不同选择、解释成本差异。模型网关的接口和部署位置会讨论清楚，但第一版不必为了"统一"而代理所有原生 CLI 的内部请求。

08｜把 Worker 放进受控环境：工作区、授权与人工接管

Worker 会读仓库、执行命令、访问知识，也可能碰到企业凭据。这节先把每项任务放入独立 Workspace，再用一个受限容器做最小的真实执行隔离；系统限定文件、工具和网络范围，给任务短期凭据，危险动作形成待审批提案，退出后撤销权限。以 Muse 的执行环境与人工确认设计为参照，再比较容器、云端 VM、MicroVM 和用户自带机器各自解决什么问题。学员做一次越权读取和一次高风险动作测试；完整 MicroVM 池保留为架构方案。

第三周：让控制面成为真正的工作系统

Worker 已经可以完成单项任务，接下来要让多人通过同一个入口安全使用它。Spring、MySQL 和日志只用于承载新的任务语义，不在这里重新讲普通 Web 开发。第三周结束时，员工关掉网页，后台任务仍可运行；回来以后还能看到状态、事件、交付物和等待自己的决定。

09｜搭起控制面：Spring 服务、存储、日志与部署

将第一周的对象落实为可运行的 Java 21/Spring Boot 服务，配置 MySQL 存储和模块边界，接好健康检查、结构化日志、配置与 Docker Compose 本地部署。先实现最小用户身份、Task 和 Event 持久化，再把控制面到 Worker 的调用方式固定下来。一次请求要能沿 requestId → taskId → attemptId → agentSessionId 找到对应执行，不依赖单机内存中的临时引用。这一讲的成果是可以启动、重启并查询既有任务状态的服务骨架。

10｜实现 Chat：接收目标，同时保持对话可继续

Chat 负责承接员工的自然语言入口、展示流式回复，并识别何时需要创建独立工作。我们实现 Session 与消息持久化、SSE 或 WebSocket 输出、取消和追加指令；对话中的长操作先交给第三周的任务接口，而不占住用户的前台连接。此时 Chat 可以先展示 Worker 事件，下一讲再补上完整的 Task 生命周期。验收时同时发起两个请求：前台继续响应，后台执行互不覆盖，刷新页面后消息仍可读。

11｜实现 Task：把目标、执行与交付分开保存

Task 是企业工作记录，不等于模型 Session。我们实现状态机、队列分派、Attempt、Agent Session 映射、事件日志、Artifact 和审批状态，把 Chat 发起的研发需求接到第二周的 Worker。需求变更可以追加到同一任务，失败重试要生成新的 Attempt，有副作用的动作需要幂等或进入结果未知状态。学员通过主动中断和恢复任务，证明能够说清"用户的目标是什么、Agent 做了什么、结果是否通过验收"，并让一次完整运行脱离网页持续存在。

12｜实现 Automation：让系统在约定时间主动创建工作

先做最容易控制的主动性：管理员配置一个定时规则，例如每天检查会员平台的失败构建，或在指定时间生成一份内容选题清单。Automation 到点产生 Trigger，经过规则校验和幂等处理后创建 Task，由原有分派与 Worker 链路执行；规则可以暂停、恢复并记录上次运行。学员在控制面重启和触发重复的情况下检查任务是否只创建一次。第四周的 IM 和外部事件会复用这条 Trigger → Task 主干。

第四周：从定时任务走向企业事件和可治理产品

前三周解决了"有人发起工作，系统能持续完成"。最后一周让工作也能由外部事件触发，并把企业知识、权限、审计和成本信息收拢到产品体验里。课程最后用研发与内容两类任务检查同一底座的复用能力。

13｜接入第一个外部信道：IM、Webhook 与事件身份

选择一个具体入口，例如 IM Bot 或代码平台 Webhook，把消息转成统一 Trigger，保存来源、外部事件 ID、所属对话 Thread、发送人和权限范围。课程不追求连接器数量，而是让一条外部消息能够安全地关联到企业用户与项目、能追溯原始事件、重复投递不重复执行。已绑定 Task 的回复直接进入对应工作，新的请求交给下一讲的过滤和分派。学员留下一个可重放的真实事件样本。

14｜事件怎样变成任务：聚合、过滤、归属与低打扰

真实群聊和 CI 消息大部分不需要 Agent 行动。先用来源、白名单、去重和 Thread 订阅做确定性 Fast Path，再对剩余候选使用模型判断；短时间内的相关事件可以合并后处理，避免重复推理与刷屏。我们会实现一条有限范围的"识别 → 聚合 → 判定 → 分派/直通"链路，保持 Router 可观察到全局进展，而不让它亲自承担耗时工作。验收数据包含闲聊、重复消息、追问、取消和真正的新需求，检查误触发、漏触发以及消耗的模型调用。

15｜SuperAgent MCP：让 Agent 获取企业能力，也让外部 Agent 使用平台

这里要区分两个方向。作为 MCP Client，SuperAgent 的 Worker 按当前任务权限读取企业知识、仓库或业务系统；作为 MCP Server，SuperAgent 向 Codex 等外部 Agent 暴露 create_task、get_task、send_task_message 等受控能力。我们会在两个方向各跑通一个最小工具，记录身份、任务作用域、调用参数、返回结果和审计事件，再让一次研发或内容任务通过它读取一条带来源的企业知识。最后用真实 Agent 与 Mock Agent 的切换检查：任务与知识权限仍由平台控制。

16｜验收一个 SuperAgent，并把项目转成工程师的能力证据

最后用两条工作路径跑完整系统：产品经理提出研发需求，Agent 修改并验证代码、等待人工验收；内容编辑提出选题，Agent 检索知识并交付可审阅草稿。我们检查 Task/Attempt/Session 是否可还原，路由、权限、成本、审计和 Artifact 是否能对上，主动触发是否有可解释的判断；再拿一次失败案例说明 Watchdog、取消或审批怎样发挥作用。学员把系统架构、关键取舍、演示、测试证据和仍未实现的生产能力整理成作品。最后讨论下一阶段是补多租户和稳定性、扩展 Agent 适配，还是深入某个业务场景。

四次阶段验收

第一周：设计能指导实现

提交一页产品定义、研发与内容两类任务的验收用例、整体架构图，以及 Task/Attempt/Session/Event/Artifact 的关系。能解释为什么 Router 的语义协调与控制面的确定性治理需要分工。

第二周：Worker 独立执行

从命令行提交一次真实任务，Worker 运行一种原生 Coding Agent，持续产生结构化事件并记录 Session 与用量；中断、取消或超时后，系统能判断后续动作。还要展示一次权限或工作区边界测试。

第三周：工作台形成端到端链路

在网页提交研发任务，控制面保存状态，Worker 在后台运行；刷新网页后仍能查看过程和交付物，任务需要确认时可暂停并继续；定时规则能够创建任务且不因重复触发重复执行。

第四周：两个业务场景复用同一底座

从一个外部事件发起任务，用 MCP 读取受授权企业知识，完成研发任务的代码与测试交付，再用同一平台完成内容草稿；能按用户、任务和 Agent 还原事件、费用、审批及引用资料。发现一个真实 Bad Case，说明修复发生在哪一层。

交付方式与练习

行动营共四周、每周四节。每节配文字资料和一次视频讲解：文字给出系统位置、核心概念与完整参考，视频展示如何做判断、借助 AI 编程推进项目、检查错误并验收结果。节外练习沿同一个仓库推进，学员提交的不只是代码，还包括产品定义、状态图、接口契约、失败记录、Trace 和演示材料。通用项目保证大家能对照同一条主线，个性化迁移则可以换成学员熟悉的行业任务。

一期的边界

"从零构建"指从产品问题和领域对象出发，完成一个可安装、可运行、可演示的最小企业 SuperAgent。课程会真正实现一条真实 Agent 执行链路、一个控制面、一种外部事件入口、一种 Automation、基础审批与审计，以及 MCP 的双向最小用例。生产级多租户、完整 SSO、海量连接器、MicroVM 池、跨机器高可用调度和全部模型的统一计费，需要更多开发与运行证据，作为后续工程路线展开。

学员可以借助 Codex 或 Claude Code 完成重复编码、测试与文档整理；人负责选择业务问题、确定架构分工、制定验收标准，并在模型和代码给出结果以后作最终判断。课程的成果是一套有证据的工程能力，以及一个能继续演进的系统，而不是一份功能数量很多的演示界面。
