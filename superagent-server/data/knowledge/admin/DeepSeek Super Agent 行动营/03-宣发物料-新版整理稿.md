统一口径与视觉方向

课程名称：「DeepSeek SuperAgent 实战营」。对外一句话：4 周、16 节课，从零构建一个可运行的企业 AI 工作系统。

主视觉用一条清楚的工作链路串联页面：员工或事件发起工作 → 控制面保存与分派任务 → Worker 调用可替换的 Coding Agent，在受控环境中执行 → 结果、用量和审计回到平台，由人验收。可使用三层方正架构图，避免把所有技术名词堆在首屏。建议沿用 SuperAgent 品牌的深蓝、亮蓝和白色，研发、内容两个场景使用同一套视觉语法。技术感来自结构和信息层级，不依赖发光机器人、抽象大脑等素材。

项目卖点以"做出可运行的最小系统"和"四次可检查的阶段产物"为准。不要把生产级多租户、完整 SSO、MicroVM 池、跨机器高可用或所有模型的统一计费写成一期交付。课程中会讨论这些演进方向。

第二屏｜为什么学

标题：会用 Coding Agent，下一步是让它成为企业能持续使用的系统

正文：你可能已经能用 Codex 或 Claude Code 完成一项开发任务。但当产品、研发、内容和运营都要通过同一个平台使用 AI，新的问题会出现：任务从哪里来，由谁执行？执行中的对话、代码和文件怎样留存？员工关掉页面后，任务能否继续？权限、费用和交付结果由谁检查？

这期行动营围绕一家公司真实会遇到的工作来搭系统。产品经理提出会员平台的开发需求，平台创建任务并调用 Coding Agent 完成代码与测试；内容编辑提出选题，同一底座获取企业知识并交付可审阅草稿。你会沿着这两条路径，建立企业 AI 工作系统的产品判断和工程主干。

视觉建议：左侧为"员工分别使用 AI 工具"的碎片化工作记录，右侧为统一 Task、执行过程、成本和交付物的工作台。比较重点是工作如何被组织与留存，不暗示个人 AI 工具没有价值。

第三屏｜你将获得什么

标题：4 周，建立 SuperAgent 的产品与工程主干

1. 系统判断：看懂持续运行的 Agent 系统，分清入口、控制面、Router、Worker 各自负责什么，并为第一版写出产品定义与验收标准。
2. 执行能力：接入一种真实 Coding Agent，管理 Session、流式事件、取消、用量和工作区，让 Worker 可以独立执行一项任务。
3. 平台能力：用 Spring Boot、MySQL 构建 Chat、Task 和 Automation，保存执行过程、交付物与人工确认，让任务离开网页也能继续。
4. 企业场景与作品：接入一个真实事件入口，跑通受权限约束的知识访问；用研发和内容两条路径验收系统，整理架构、关键取舍与演示证据。

收束句：课程结束时，你带走的是一个可运行的最小系统，以及能讲清设计、实现、验证和未完成边界的工程作品。

第六屏｜课程目录

标题：16 节课，做出企业 SuperAgent 的主链路

第一周：思考、产品与架构
阶段目标：确定第一版要服务谁、完成哪项工作，画出可指导实现的系统边界。
01｜AI 工程师怎样看一个持续工作的 Agent 系统
02｜如果我来做 SuperAgent：先确定第一版要完成什么
03｜从员工和管理员视角设计企业 AI 工作台
04｜画清 SuperAgent 架构：控制面、Router 与 Worker

第二周：Worker 运行层
阶段目标：让一种真实 Coding Agent 在受控工作区独立执行，留下可追踪的状态与用量。
05｜两种 Agent Runtime：自建 Loop 与原生 Coding Agent
06｜运行时怎样持续工作：状态、异步与 Watchdog
07｜谁来做这项工作：Agent 选择、模型路由与用量归因
08｜把 Worker 放进受控环境：工作区、授权与人工接管

第三周：控制面与工作入口
阶段目标：把员工的对话变成可持久、可恢复、可验收的工作任务。
09｜搭起控制面：Spring 服务、存储、日志与部署
10｜实现 Chat：接收目标，同时保持对话可继续
11｜实现 Task：把目标、执行与交付分开保存
12｜实现 Automation：让系统在约定时间主动创建工作

第四周：事件驱动与企业场景
阶段目标：从员工主动提问扩展到事件触发，完成研发与内容两类任务的验收。
13｜接入第一个外部信道：IM、Webhook 与事件身份
14｜事件怎样变成任务：聚合、过滤、归属与低打扰
15｜SuperAgent MCP：让 Agent 获取企业能力，也让外部 Agent 使用平台
16｜验收一个 SuperAgent，并把项目转成工程师的能力证据

第七屏｜4 次阶段检测

标题：每周一次成果验收，项目进度看得见

- 第一周：一页产品定义、研发与内容任务验收用例、架构图和最小 Worker 契约。
- 第二周：Worker 从命令行完成真实任务，展示事件、Session、用量及一次隔离或权限边界测试。
- 第三周：员工从页面发起任务；刷新后能查看后台执行、交付物与人工确认；定时任务能避免重复执行。
- 第四周：外部事件进入同一任务链路；研发和内容场景各跑通一次，并能还原费用、审计、知识来源与失败案例。

视觉建议：四张"证据卡"分别展示产品定义、执行事件、Task 页面、双场景交付。使用课程真实产物截图，未完成时先用结构占位，发布前替换。

第八屏｜技术栈与可迁移场景

标题：在一个项目里，把已有软件工程经验接到 Agent 系统上

技术栈：Java 21、Spring Boot、MySQL、Docker Compose 构建控制面；以一种真实 Coding Agent CLI 和一种 Mock Agent 验证可替换的 Worker 契约；使用 SSE 或 WebSocket 输出事件，用 MCP 接入企业能力；采用任务级工作区与受限容器完成最小隔离。Watchdog、成本归因、审批、事件过滤都服务于这条主链路。

注：前端框架、外部 IM 平台、具体 CLI 供应商和本地依赖安装方式以开营前的教学仓库为准，不在宣发物料中承诺唯一选择。MicroVM、完整 SSO 与高可用调度为架构讨论和后续演进方向。

可迁移场景：
- 研发：产品提出需求，Agent 修改代码、运行测试并提交可审阅结果；发布由人确认。
- 内容生产：编辑提交选题，Agent 在授权范围内读取企业知识，形成带来源、可审阅的草稿。
- 继续扩展：把入口、工具和验收标准替换成运营数据整理、内部知识处理等工作；任务、运行与治理主干可复用。

视觉建议：以"同一个底座 → 两个业务场景"为主，不把三个场景画成课程都会完整实现的承诺。
